한 문장으로 꿰기 데이터를 나누고(train/test), 스케일을 맞추고(Pipeline), 손실함수(MSE)를 최소화해 파라미터(coef_)를 학습한다. 이때 하이퍼파라미터(alpha)로 규제 세기를 조절해 과적합과 과소적합 사이의 균형점을 찾는데, 그 균형점은 GridSearchCV가 교차검증 점수로 찾아준다.

핵심 구분 3가지

1. 파라미터 vs 하이퍼파라미터

가장 많이 헷갈리는 지점이자 가장 자주 물어보는 것입니다.

노트북에 나오는 모든 표(alpha, max_depth, C, epsilon, hidden_layer_sizes…)가 전부 하이퍼파라미터 목록입니다.

2. 규제 3형제

LinearRegression ──┬── + L2 ──→ Ridge        계수를 0 쪽으로 축소, 변수는 전부 유지
   (규제 없음)      ├── + L1 ──→ Lasso        계수를 정확히 0으로 → 변수 선택 효과
                    └── + 둘다 ─→ ElasticNet   l1_ratio로 비율 조절 (0.0=Ridge, 1.0=Lasso)

3. 스케일링이 필요한 모델 / 아닌 모델

필요함 — 크기를 직접 계산하는 모델
  • Ridge · Lasso · ElasticNet — 규제가 계수 크기 기준
  • SVR — 거리 기반 커널
  • KNN — 거리 계산
  • MLP — 경사하강법으로 학습
불필요 — 순서만 보는 모델
  • LinearRegression — 규제가 없어 계수 크기가 무관
  • DecisionTree — 분할 기준이 크기가 아닌 순서
  • RandomForest · GradientBoosting — 같은 이유

이것 하나만 기억하면 됩니다 train 점수와 CV 점수의 격차 = 과적합의 크기. alpha를 키우면 계수 크기가 줄고(2468 → 17), 격차도 줄지만, 너무 키우면 두 점수가 함께 무너집니다.
alpha는 절대값이 아니라 데이터 스케일에 상대적입니다 load_diabetes()의 X는 이미 정규화되어 있습니다(각 열의 제곱합 = 1, 값의 범위 −0.14 ~ 0.20). 그래서 노트북 셀 14의 ElasticNet(alpha=0.1)은 이 데이터에서 엄청나게 강한 규제가 되어 R²가 0.099로 무너졌습니다. 계수 절댓값 합이 3843 → 204로 짓눌려 사실상 평균만 예측하는 모델이 된 것입니다.

대처: 규제 모델은 항상 StandardScaler와 함께 Pipeline으로 묶고, alpha는 손으로 고르지 말고 GridSearchCV로 찾으세요.

결론 — 이 노트북에서 배울 진짜 교훈
  1. 표준편차가 0.10을 넘습니다. 상위 7개 모델의 차이(0.44~0.47)는 표준편차 안에 묻혀 통계적으로 구분되지 않습니다. 단일 test set 점수로 순위를 매기면 안 됩니다.
  2. 복잡한 모델이 항상 좋은 게 아닙니다. 442행 × 10열은 트리·부스팅·신경망이 패턴을 학습하기엔 너무 작고, 관계 자체가 선형에 가깝습니다.

시험 · 면접 단골

Ridge와 Lasso의 차이는?
둘 다 과적합을 막는 규제 기법이지만 벌점의 형태가 다릅니다. Ridge(L2)는 계수의 제곱합에 벌점을 주어 계수를 0 쪽으로 줄이지만 정확히 0으로 만들지는 않아 모든 변수가 남습니다. Lasso(L1)는 계수의 절댓값 합에 벌점을 주어 일부 계수를 정확히 0으로 만들기 때문에 자동 변수 선택 효과가 있습니다.
파라미터와 하이퍼파라미터의 차이는?
파라미터는 모델이 데이터를 보고 스스로 학습하는 값입니다(coef_, intercept_). 하이퍼파라미터는 학습을 시작하기 전에 사람이 정해주는 값입니다(alpha, max_depth, C). 하이퍼파라미터는 GridSearchCV 같은 방법으로 탐색해서 정합니다.
alpha를 키우면 어떻게 되나?
규제가 강해져 계수가 작아지고 모델이 단순해집니다. 과적합은 줄어들지만 너무 키우면 과소적합이 됩니다. 실측하면 alpha가 0.001에서 10000으로 갈 때 계수 절댓값 합이 2468에서 17로 줄고, CV R²는 0.40 → 0.45(최고, alpha=100) → 0.08로 올라갔다 떨어집니다.
과적합인지 어떻게 판단하나?
학습 점수와 검증 점수의 격차를 봅니다. train R²는 높은데 CV R²가 낮으면 과적합입니다. 둘 다 낮으면 과소적합이고요. 그래서 cross_validate(..., return_train_score=True)로 두 점수를 같이 봐야 합니다.
왜 test 데이터에 fit을 하면 안 되나?
테스트셋의 평균·표준편차 같은 정보가 학습 과정에 새어 들어가기 때문입니다(데이터 누수). 그러면 평가 점수가 실제보다 좋게 나와, 실제 서비스에서의 성능을 알 수 없게 됩니다. Pipeline으로 묶으면 교차검증의 각 fold에서 자동으로 train에만 fit이 적용되어 구조적으로 막힙니다.
왜 SVR·KNN은 스케일링이 필요하고 DecisionTree는 필요 없나?
SVR과 KNN은 거리를 계산합니다. 단위가 큰 특성 하나가 거리를 지배해버리므로 스케일을 맞춰야 합니다. 반면 트리는 "이 값이 임계값보다 큰가?"라는 순서만 보기 때문에, 값에 어떤 단조 변환을 해도 분할 결과가 같아 스케일링이 무의미합니다.
R²가 음수가 나올 수 있나?
네. R² = 1 − SS_res/SS_tot 이므로, 모델의 오차가 단순히 평균으로 예측한 것보다 클 때 음수가 됩니다. 위 비교표에서 DummyRegressor의 CV R²가 −0.0297인 것이 그 예입니다.
다항 회귀의 degree를 무작정 키우면?
특성 개수가 폭발적으로 늘어(차원의 저주) 과적합합니다. 실측하면 10개 특성 기준 degree=1일 때 CV R² 0.4658, degree=2에서 0.4413, degree=3에서 0.0111로 붕괴합니다(열이 286개로 증가). degree도 GridSearchCV로 찾아야 하는 하이퍼파라미터입니다.
