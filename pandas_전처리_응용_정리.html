3단계 · 채우기 (fillna 계열)

① 대표값으로 — 평균 · 중앙값 · 최빈값

df_1 = df.copy()

df_1['age'] = df_1['age'].fillna(df_1['age'].mean())        # 평균 26.25
df_1['bmi'] = df_1['bmi'].fillna(df_1['bmi'].median())      # 중앙값 25.95
df_1['gender'] = df_1['gender'].fillna(df_1['gender'].mode()[0]) # 최빈값 'F'
mode()에 [0]이 붙는 이유

mean()·median()은 값 하나를 돌려주지만, mode()는 Series를 돌려줍니다. 최빈값이 여러 개 있을 수 있기 때문입니다 (M 2개, F 2개면 둘 다 최빈값). 그래서 [0]으로 첫 번째 것을 꺼내 씁니다.

③ 보간 — interpolate()

앞뒤 값을 그대로 복사하는 대신 사이를 계산합니다. 숫자 열에만 적용됩니다. 

import numpy as np

numeric_cols = df.select_dtypes(include=[np.number])   # 수치형만 추출
df_linear = numeric_cols.interpolate(method='linear')  # 직선으로 잇기

# 시간 간격을 고려한 보간 — 인덱스가 DatetimeIndex일 때만 작동
df_6 = df.set_index('date')
numeric_cols = df_6.select_dtypes(include=[np.number])
df_time = numeric_cols.interpolate(method='time')
method='time'의 전제 조건

method='time'은 인덱스가 DatetimeIndex일 때만 작동합니다. 그래서 먼저 set_index('date')로 날짜를 인덱스로 올려야 합니다. 'linear'는 행 간격을 모두 같다고 보고 채우지만, 'time'은 실제 시간 간격에 비례해서 채웁니다 — 측정 간격이 불규칙한 센서 데이터에 중요합니다.

④ 예측 기반 — KNNImputer

비슷한 행을 찾아서 그 값으로 채웁니다. 나이와 BMI가 비슷한 사람들의 값을 참고하는 식입니다. 결측률이 높지만 버릴 수 없는 중요한 변수에 씁니다. 

from sklearn.impute import KNNImputer

numeric_df = df[['age', 'bmi']]              # 수치형 변수만

imputer = KNNImputer(n_neighbors=2)             # 가장 가까운 이웃 2개 참고
df_knn = pd.DataFrame(imputer.fit_transform(numeric_df),
                      columns=numeric_df.columns)

df[['age', 'bmi']] = df_knn                  # 원본에 다시 대입
주의 두 가지
  1. fit_transform()의 결과는 NumPy 배열입니다. 열 이름이 사라지므로 pd.DataFrame(..., columns=...)으로 다시 감싸야 합니다.
  2. 수치형 열만 넣을 수 있습니다. 문자열이 섞이면 오류가 납니다. select_dtypes(include=[np.number])로 걸러내세요.

단위 환산 — 비교 가능하게 만들기

거리는 km인데 시간은 분, 어떤 데이터는 마일. 이대로는 계산도 비교도 안 됩니다. 기준을 하나로 통일하는 것이 목적입니다. 외국 데이터를 국내 기준에 맞출 때도 같은 작업이 필요합니다. 

df['Distance_m'] = df['Distance_km'] * 1000   # km → m
df['Time_hr']    = df['Time_min'] / 60       # 분 → 시간

열 전체에 곱셈·나눗셈이 한 번에 적용되는 것을 벡터 연산이라고 합니다. 반복문 없이 이렇게 쓰는 것이 판다스의 기본이자 가장 빠른 방법입니다.

자료형 변환 — dtype 맞추기

CSV에서 읽으면 숫자가 문자열로, 날짜가 그냥 글자로 들어오는 일이 흔합니다. dtype이 틀리면 계산도 정렬도 엉망이 됩니다 — 문자열 '25'와 '100'을 정렬하면 '100'이 앞에 옵니다. 

print(df.dtypes)   # 변환 전 확인 — 항상 먼저!

df['Age'] = df['Age'].astype(int)              # 문자열 숫자 → 정수
df['JoinDate'] = pd.to_datetime(df['JoinDate'])   # 문자열 → 날짜
df['Gender'] = df['Gender'].astype('category')   # 문자열 → 범주형

print(df.dtypes)   # 변환 후 확인
변환왜 하는가
astype(int) 문자열로 읽힌 숫자를 계산 가능하게. 결측치가 있으면 실패하므로 먼저 채워야 한다
pd.to_datetime() 날짜 계산·정렬·.dt 접근자 사용 가능. df['날짜'].dt.year처럼 연·월·일을 바로 꺼낼 수 있다
astype('category') 메모리 절약(반복되는 문자열을 숫자 코드로 저장)과 순서 지정 가능. groupby에서 observed 옵션과 연결된다

② 변환 (Transformation)

def z_score(x):
    return (x - x.mean()) / x.std()

df['score_zscore'] = grouped['score'].transform(z_score)

③ 필터링 (Filtration)

filter의 결과를 읽는 법

함정 ② — str.contains는 부분 일치다

'할리스'로 검색하면 '서울고무상사할리스종로5가점' 같은 상호도 걸립니다. 브랜드명이 상호 중간에 들어간 경우까지 잡히기 때문입니다.

정확도가 중요하면 str.startswith()를 쓰거나, str.contains()로 1차 추출한 뒤 .unique()로 실제로 어떤 상호들이 걸렸는지 눈으로 확인하는 단계를 반드시 넣으세요. 노트북에서 .unique()를 호출하는 셀이 바로 이 검증입니다.

.copy()를 붙이는 이유

필터링 결과는 원본의 일부를 참조하는 뷰(view)일 수 있습니다. 여기에 새 열을 추가하면 SettingWithCopyWarning이 뜨고, 경우에 따라 값이 반영되지 않습니다. 필터링한 결과를 수정할 계획이라면 .copy()로 명시적인 복사본을 만드세요.

① 문자열 끝의 보이지 않는 공백
증상

증상

필터링 결과가 원본을 참조하는 뷰(view)라서.
해결
필터링 직후 .copy()를 붙여 명시적 복사본을 만든다.
③ OrdinalEncoder의 알파벳순 정렬
증상
low/medium/high가 1/2/0이 되어 순서가 뒤죽박죽.
원인
기본값이 알파벳순이라 high가 0번이 된다.
해결
categories=[['low','medium','high']]로 순서를 직접 지정.
④ pd.cut의 labels 개수 불일치
증상

원인
경계 5개는 구간 4개를 만드는데 라벨을 5개 줬다.
해결
labels 개수 = bins 개수 − 1을 지킨다.
⑤ mode()를 그대로 사용
증상

원인
mode()는 값이 아니라 Series를 반환한다.
해결
mode()[0]으로 첫 번째 최빈값을 꺼내 쓴다.
⑥ agg()에 사용자 정의 함수 + numeric_only
증상
사용자 함수를 agg 리스트에 넣고 numeric_only=True를 주면 오류.
원인
두 옵션을 함께 지원하지 않는다.
해결
grouped['score'].agg([...])처럼 열을 먼저 지정한다.

증상
모델 성능이 검증에서는 좋은데 실전에서 급락.
원인
bfill()이 미래 값으로 과거를 채워 실전에 없는 정보를 학습시켰다.

시계열 예측에서는 ffill()만 쓴다.
